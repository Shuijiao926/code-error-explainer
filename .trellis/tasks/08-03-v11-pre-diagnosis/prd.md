# 产品重定位 V1.1：前置分诊 + 项目AI联动诊断

## Goal & User Value

**把报错前置分诊成人话说明 + 一份能直接交给项目 AI 做最终诊断的结构化诊断包。**

当前 V1.0 定位有偏差：它拿不到完整代码上下文，给不出"项目级根因诊断报告"。
重定位后，工具明确退回到**前置分诊**这一层：

```
报错/堆栈 → 前置分诊报告（人话版 + 项目AI诊断包）→(复制诊断包)→ 项目AI
           → 结合仓库上下文的最终诊断 →(回填)→ 历史闭环踩坑档案
```

**边界：工具不做最终诊断**（无仓库上下文），只负责"说明白是什么问题、什么技术栈、
技术使用哪里可能不妥、还缺什么信息"。

## Confirmed Facts（头脑风暴已确认）

- **定位**：报错前置分诊工具，不做最终项目级诊断（最终诊断交给项目 AI）。
- **受众**：非 IT / 初级开发也能看懂——人话优先，技术术语要解释。
- **报告结构**：**双段式**。
  - 人话版：一句话定性 / 出在哪一层 / 疑似技术使用不妥（方向，非断言）。
  - 项目AI诊断包：原始报错 + 预判 + 待查证项 + 请求结合仓库上下文给根因与修复方案。
- **技术栈识别**：从堆栈特征**自动识别**（Spring/MyBatis/Jackson/Tomcat…），**用户可修正**；识别不出标"通用/未知"。
- **历史闭环**：存「原始报错 + 技术栈 + 预判报告」；支持**回填项目 AI 的最终诊断**；按异常类型/技术栈/关键字搜索。
- **联动方式**：一键**复制诊断包**交给项目 AI（默认实现）。
- 技术栈：保持 React + AntD5 前端、Spring Boot 4 + MyBatis-Plus 后端（沿用 V1.0 基建）。

## Requirements（范围内）

### R1 前置分诊（核心，重写 V1.0 的 explain 输出）
- `POST /api/explain` 入参：`{stackTrace, techStack?}`（techStack 为用户可选的修正值）。
- 技术栈自动识别：堆栈特征（类名前缀）→ 框架标签列表；识别不出 → `["通用/未知"]`。
- AI 按「分诊」角色输出**双段式**：
  - 人话版：`summary`（一句话定性）/ `layer`（出在哪一层）/ `misuse`（疑似技术使用不妥，人话）/ `nextStep`（你现在可以怎么做，引导复制诊断包）。
  - 诊断包：`techStack` / `suspectedPoints`（疑似不妥，技术向）/ `checkList`（待查证项）/ 原始报错。
- 异常类型提取沿用 V1.0 正则。
- 结果自动入库。

### R2 历史闭环（扩展 V1.0 历史模块）
- 列表/详情存：原始报错、异常类型、技术栈、人话版摘要、预判报告。
- `PUT /api/history/{id}/diagnosis` 回填最终诊断（自由文本，可空）。
- 搜索：异常类型 / 技术栈 / 关键字。
- 单删 / 清空沿用。

### R3 前端
- 输入区下方展示**自动识别的技术栈**，可点击修正。
- 报告卡片改**双段式**：人话版（通俗）+ 诊断包（可一键复制给项目 AI）。
- 历史抽屉：显示技术栈标签；支持回填诊断入口；搜索增强。
- 深色模式沿用。

## Acceptance Criteria

- [ ] AC1 后端 `mvn test` 通过；前端 `npm run build` 通过。
- [ ] AC2 `POST /api/explain` 返回双段式结构（人话版 + 诊断包），无 Key 时 Mock 也能产出完整双段式。
- [ ] AC3 技术栈识别正确：NPE+Spring 堆栈 → 识别出 Spring 系框架；纯 SocketTimeout → 识别不出标"通用/未知"。
- [ ] AC4 用户传 `techStack` 时，报告以用户修正值为准。
- [ ] AC5 诊断包可一键复制为一段可直接喂给项目 AI 的提示词文本。
- [ ] AC6 历史记录可回填最终诊断、按技术栈搜索。
- [ ] AC7 数据库 `error_history` 新增字段迁移脚本可用（对已有库幂等）。

## Out of Scope（后续阶段）

- 工具内直接调用项目 AI（MCP/CLI 集成）——明确不做。
- 多语言报错（Python/Node/Go）——仍以 Java 为主。
- 内置"异常×技术栈"知识卡片库（可作为 V1.2 优化疑似不妥的离线可用性）。
- 用户系统、多人协作。

## Key Decisions（详见 design.md）

1. 报告 DTO 重构为 `PreTriageReport{personReport, handoff}`，替换 V1.0 五要素。
2. 技术栈识别 = 内置特征规则表（类名前缀→框架），后端执行，结果可被用户修正。
3. AI 提示词改为「分诊专家」角色；诊断包为结构化字段，前端拼复制文本。
4. 历史表加 `tech_stack` / `pre_report` / `final_diagnosis` 字段（幂等迁移）。
