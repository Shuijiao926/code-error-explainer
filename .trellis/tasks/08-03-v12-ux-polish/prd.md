# V1.2 交互体验优化：简化输入 / 历史详情 / 全流程打磨

## Goal & User Value

把交互做到"**技术小白也能顺畅用**"：
1. **输入极简**——只粘贴 Java 异常堆栈，点生成即可（技术栈由后端静默识别，不做输入项）。
2. **历史可看详情**——历史里直接查看完整分诊报告与诊断回填记录，不用跳回主页。
3. **全流程无死角**——空状态有引导、生成中有提示、误粘贴有软校验、复盘可筛选。

## Confirmed Facts（V1.1 现状 + 用户 review 结论）

- V1.1 已交付：双段式报告 / 技术栈自动识别 / 复制诊断包 / 历史多条追加回填 / 状态标签。
- 用户 review 三点结论：
  1. **去掉技术栈选择**：技术小白不清楚技术栈，输入区下拉多选 + `/api/detect` 预填应移除；识别放后端静默进行，结果里仍展示识别结果。
  2. **历史缺详情查看**：点异常类型跳主页不直观；改为历史抽屉内开**详情层**，完整展示报告 + 诊断回填。
  3. **用户旅程深挖**：空状态引导 / 生成中提示 / 非堆栈软提示 / 历史状态筛选。
- 技术栈：React + AntD5 前端、Spring Boot 4 + MyBatis-Plus 后端（沿用）。

## Requirements（范围内）

### R1 简化输入（Phase 1）
- 移除输入区技术栈下拉多选与自动识别预填。
- 移除 `POST /api/detect` 接口与 `ExplainRequest.techStack` 覆盖参数。
- 后端 `TechStackDetector` 保留并继续自动识别；结果卡片仍展示"技术栈"作为输出信息。
- `AIService.explain(stackTrace, techStack)` 内部仍传识别结果（接口签名可保留，入参来源改为仅后端识别）。

### R2 历史详情查看（Phase 2）
- 历史列表每条提供「详情」入口，在历史抽屉内打开**详情层**（嵌套 Drawer 或同抽屉内容切换）。
- 详情层展示：异常类型 + 技术栈 + 时间；人话版四段；项目AI诊断包（suspectedPoints/checkList + 复制按钮）；诊断回填记录（多条，可追加）。
- 移除"点异常类型跳主页"的旧交互（或保留但不作为详情入口）。

### R3 交互细节（Phase 3）
- 空状态：给出引导文案 + 「试试示例堆栈」按钮（自动填入一段 NPE 示例）。
- 生成中：按钮 loading 旁提示"通常需要 5-30 秒"；Key 失效/超时给明确错误提示。
- 非堆栈软提示：粘贴内容不像 Java 堆栈时温和提示（仍可生成）。
- 历史状态筛选：按「全部 / 待回填 / 已诊断」过滤。

### R4 验证与文档（Phase 4）
- 全流程走查（进入→粘贴→生成→复制→回填→筛选详情）。
- README 交互流程说明更新。
- 全量 `mvn test` + `npm run build` 通过。

## Acceptance Criteria

- [ ] AC1 输入区无技术栈选择控件；粘贴堆栈 + 生成即可出双段式报告。
- [ ] AC2 结果卡片仍显示自动识别的技术栈；后端识别逻辑保留。
- [ ] AC3 历史列表可打开详情层，展示完整报告 + 诊断回填记录（可追加）。
- [ ] AC4 详情层的「复制诊断包」可用。
- [ ] AC5 空状态有引导 + 示例按钮；生成中有时长提示；误粘贴有软提示；历史可按状态筛选。
- [ ] AC6 `mvn test` 15+ 用例全绿；`npm run build` 通过。

## Out of Scope（后续）

- 多语言报错（Python/Node/Go）——仍限 Java。
- 粘贴即自动触发生成（不自动，仍需点按钮）。
- 用户系统、协作。

## Key Decisions

1. 技术栈识别完全后台化，前端零输入项。
2. 历史详情用抽屉内嵌套 Drawer 呈现。
3. 状态筛选为"全部/待回填/已诊断"三段。
4. 软提示仅警告不阻断生成。
