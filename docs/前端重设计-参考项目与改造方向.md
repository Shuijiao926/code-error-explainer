# 第一部分：参考项目清单

按"看什么"分四类，每条注明**该看它哪一点**。

## A. 教育型产品设计标杆（最该看，看"结构"）

### 1. explainshell.com —— 把一段看不懂的东西拆成小块逐个解释 ★最推荐

- 网址：https://explainshell.com/
- 开源：https://github.com/idank/explainshell
- 它做什么：输入一条复杂 Shell 命令，它把命令**按参数逐段拆开**，每段悬停显示对应的人话解释。
- **该抄什么**：
  - 「**整体 → 拆解 → 逐块解释**」的呈现结构。这正是我们该对异常堆栈做的事：整条堆栈先一句话定性，再逐行/逐帧解释。
  - 悬停联动：鼠标放到解释上，高亮对应的原始片段。
- 局限：解释来自 man 手册，语言偏文档化——比我们想要的还不够"人话"。

### 2. MDN 中文 · JavaScript 错误参考 —— 「错误说明」的黄金模板 ★最推荐

- 网址：https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Errors
- 它做什么：每种 JS 错误一个独立页面。
- **该抄什么**：它的页面结构几乎可以直接作为我们的报告模板——
  ```
  错误消息 → 错误类型 → 哪里出错了 → 常见原因 → 示例代码 → 怎么修 → 相关概念
  ```
  我们的知识卡片/分诊结果，就应该按这个结构组织，而不是"一段 AI 生成的散文"。

### 3. Python Tutor —— 把抽象执行过程变得可见

- 网址：https://pythontutor.com/
- 开源：https://github.com/pgbovine/OnlinePythonTutor
- 它做什么：逐行可视化代码执行，内存、变量、调用栈一步步展示。
- **该抄什么**：「**一步一步**」而不是一次性甩结果。新手最怕的是一屏信息。可以用来设计"堆栈逐帧解释"的交互。

### 4. roadmap.sh —— 学习路径的可视化标杆 ★最推荐

- 网址：https://roadmap.sh/
- 开源：https://github.com/kamranahmedse/developer-roadmap
- 它做什么：把"学一门技术要学什么"画成节点图，可按自己进度点亮。
- **该抄什么**：我们 V2.0 设计的「概念图谱 + 学习路径」，视觉呈现直接学它——**节点 + 依赖连线 + 已完成状态**。

### 5. Exercism —— 学习轨道 + 即时反馈

- 网址：https://exercism.org/
- **该抄什么**：「轨道（Track）」概念——把零散概念组织成一条可走完的路线，每完成一步有明确反馈。对应我们的"学习路径 + 已学标记"。

### 6. Rust 错误索引 / Elm 编译器错误 —— 业界公认最友善的错误信息

- Rust：https://doc.rust-lang.org/error_codes/error-index.html
- Elm：https://elm-lang.org/
- **该抄什么**：
  - 友好语气（"别担心，这个错误很常见"）
  - 每个错误都有**编号 + 一句话说明 + 示例 + 建议**
  - Rust 的 `rustc --explain E0308` 形式：**一个错误 = 一个可展开的说明条目**，和我们的知识卡思路一致。

## B. 同类竞品（AI 报错解释，看"别人做到哪一步"）

这些项目大多停留在"贴进去 → 吐一段 AI 回答"，**没有一个把教育链路做完整**——这正是我们的机会。

| 项目 | 链接 | 一句话 | 可借鉴 / 可超越 |
|---|---|---|---|
| OtterDr | https://github.com/OtterDr/OtterDr | "Errors explained by AI, featuring your favorite otter pal 🦦"（VS Code 插件） | 唯一强调"亲切感"的（水獭形象）；但只做单次解释 |
| ErrEase | https://github.com/HiLakshya/ErrEase | 简化报错理解的 Web 工具 | 输入区做得很简单，学它的"零门槛首屏" |
| AI-Error-Explainer | https://github.com/laiba2103/AI-Error-Explainer | AI 解释编程错误并给修复建议 | 输出结构可以对比 |
| ai-stack-trace | https://github.com/lxgicstudios/ai-stack-trace | 粘贴堆栈 → 给方案 | 极简，但没有沉淀与学习 |
| logshed | https://github.com/logshed/logshed | 自建日志平台，附 AI 解释错误 | 面向运维，不是新手 |

> **共同缺口**：都只解决"这一次"，不解决"下次遇到同类错误我懂不懂"。这就是我们要做的差异化。

# 第二部分：改造方向

## 1. 现在前端的问题：术语全是给开发看的

我把现有前端界面里的文案扫了一遍，问题很集中：

### 导航层（新用户第一眼就看到）

| 现在 | 小白看到的 | 问题 |
|---|---|---|
| 分诊 | ？？？ | 医疗词，不知道是干嘛的 |
| 异常速查 | 大概是查错误？ | 还行但"异常"是行话 |
| 踩坑知识库 | 踩坑？ | 内部黑话 |
| 历史 | 历史记录 | 勉强 |
| 调用日志 | 完全不懂 | 纯开发术语，不该出现在主导航 |

### 内容层

| 现在 | 问题 |
|---|---|
| 异常堆栈 / 堆栈 | 行话 |
| 技术栈 | 行话 |
| 异常类型 | 行话 |
| 前置分诊报告 | 行话 + 不理解 |
| 项目 AI 诊断包 / handoff | 行话，且默认用户有"项目 AI" |
| 沉淀 / 回填 | 内部黑话 |
| Provider / token / fallback / Mock | 纯开发术语，出现在页面上 |
| KPI / 分布 / 归一化 | 运营术语 |

**结论：现在的界面是"开发者给自己做的工具"，不是"给新手用的产品"。**

## 2. 从参考项目提炼的 6 条设计原则

| # | 原则 | 来源 |
|---|---|---|
| 1 | **对象拆解**：一整段看不懂的东西 → 拆成小块，逐块解释 | explainshell |
| 2 | **固定结构**：解释不是一段散文，而是「是什么/在哪/为什么/怎么办/去哪学」的固定骨架 | MDN 错误参考 |
| 3 | **一步一步**：一屏只讲一件事，用户可以按"下一步"推进 | Python Tutor / Duolingo |
| 4 | **路径可见**：概念之间的前置关系和进度要能看见 | roadmap.sh / Khan Academy |
| 5 | **语气鼓励**：报错是常事，不要用审判式语气 | Duolingo / Elm |
| 6 | **术语消失**：所有面向用户的文案不允许出现未解释的技术词 | 全部参考项目的共性 |

## 3. 建议的新信息架构

### 导航从 5 项砍到 3 项

```
现在：[分诊] [异常速查] [踩坑知识库] [历史] [调用日志]
改为：[看报错] [学习中心] [我的记录]        …… [调用日志] 收进"高级/设置"
```

| 新导航 | 对应现在 | 说明 |
|---|---|---|
| **看报错** | 分诊 | 首页唯一的输入入口，直接叫"看报错" |
| **学习中心** | 异常速查 + 踩坑知识库 + 新增概念图谱 | 把"查资料"和"看别人的坑"合并成学习场景 |
| **我的记录** | 历史 | 口语化 |
| （隐藏）调用日志 | 调用日志 | 移到设置页/高级模式，默认不展示 |

### 术语对照表（全部界面统一替换）

| 现在 | 改为 |
|---|---|
| 分诊 / 前置分诊 | 看懂这条报错 / 分析 |
| 异常堆栈 | 报错信息（粘贴区可附一句示例说明） |
| 技术栈 | 你用的工具（或直接不展示，收进"详情"） |
| 异常类型 | 错误名称 |
| 前置分诊报告 | 报错说明 |
| 人话版 | 说人话 |
| 项目 AI 诊断包 | 交给 AI 继续查（附一句"复制给 ChatGPT / Claude 等"） |
| 诊断回填 | 记录最终答案 |
| 沉淀 / 踩坑知识库 | 收藏 / 我的经验 |
| 异常速查 | 常见报错 |
| 调用日志 | 系统记录（高级） |
| Provider / token / fallback / Mock | 全部移出用户可见区域 |

## 4. 首屏重新设计（最关键的一屏）

**现在**：一个大文本框 + "粘贴 Java 异常堆栈" + 一堆速度卡片 + 三步引导 + 最近记录。

**建议**：像 MDN + Duolingo 的结合体，一屏只做一件事：

```
┌─────────────────────────────────────────┐
│  别慌，把报错贴进来，我帮你看懂           │
│                                         │
│  ┌───────────────────────────────────┐  │
│  │  （粘贴区，占位符写真实例子）       │  │
│  └───────────────────────────────────┘  │
│  [ 帮我看看 ]   [ 不知道贴什么？看示例 ] │
│                                         │
│  ✓ 不用懂技术词   ✓ 免费   ✓ 3 分钟看懂 │
└─────────────────────────────────────────┘
```

点击后进入**分步结果页**（学 Python Tutor / MDN 结构）：

```
第 1 步  这是什么错
        一句话 + 生活类比

第 2 步  你在做哪一步时出错的
        操作场景描述

第 3 步  为什么会这样
        人话原因 + 新手最常犯的错

第 4 步  这里面有 3 个词你可能不认识
        [空指针] [依赖注入] [连接池]  ← 点开就是人话解释

第 5 步  想彻底搞懂？按这个顺序学
        1. 什么是对象 → 2. 什么是引用 → 3. 空指针
        每条挂 1-2 个资料链接（带阅读时长）

第 6 步  现在可以做什么
        □ 检查第 47 行
        □ 复制给 AI 继续查
        □ 先去看看"空指针"是什么

[ 我看懂了 ]  [ 还有点懵 ]  ← 反馈
```

这套结构直接对应 explainshell（拆解）+ MDN（固定骨架）+ Python Tutor（分步）+ roadmap.sh（路径）。

## 5. 视觉风格建议

- **降低信息密度**：现在一屏塞了 5 个模块，新手不知道看哪
- **卡片留白 + 大字号**：面向非技术用户，字号和行距要大于开发者工具
- **颜色只表达一件事**：友好/提示用蓝绿，不要用红色警报色（报错本身已经让人焦虑）
- **保留 Ant Design 组件**：不需要换技术栈，只换信息架构和文案

## 第 2 版调整（2026-11-04）

> 本轮三项变更：**① 导航从顶部改到左侧；② 品牌换成英文 slogan；③ 按角色拆分菜单。**

### 布局：顶部导航 → 左侧固定侧边栏

```
┌────────────────────┬──────────────────────────────────────────────┐
│                    │                                              │
│   ⚙  Make errors   │                                              │
│     make sense.    │              主内容区                         │
│                    │                                              │
│  ───────────────   │                                              │
│  ▸ 分诊            │                                              │
│  ▸ 速查            │                                              │
│  ▸ 历史记录        │                                              │
│                    │                                              │
│                    │                                              │
│                    │                                              │
│  ───────────────   │                                              │
│  ⚙ 设置            │                                              │
│  👤 张三 ▾         │                                              │
└────────────────────┴──────────────────────────────────────────────┘
```

**侧边栏规格**

| 项 | 规格 |
|---|---|
| 宽度 | 展开 220px / 折叠 64px（可收起，图标模式） |
| 品牌区 | 高度 88px，主 slogan 两行排，字号 15px，字重 600 |
| 菜单项 | 高 44px，图标 16px + 文字 14px，间距 8px |
| 选中态 | 左侧 3px 色条 + 浅色背景，**不**用卡片阴影 |
| 分区 | 主功能与「设置/用户」之间加分隔线与 16px 留白 |
| 底部 | 固定显示当前用户名与角色，点击展开菜单（设置 / 退出登录） |

### 角色菜单

**普通用户**（3 项）

```
分诊
速查
历史记录
```

**管理员**（2 项）

```
用户管理
调用日志
```

> 说明：
> - 原「踩坑知识库」不单独占菜单，**并入「速查」页的第二个 Tab**（常见报错 / 我的经验），避免菜单膨胀。
> - 原「调用日志」从普通用户视野彻底移除。
> - 角色差异在**登录后按 `role` 动态生成菜单**；后端接口同时按 role 校验，不能只靠前端隐藏。
> - 建议管理员也具备普通用户能力（全部菜单 + 管理区两块），实现上更自然；若坚持"管理员只看两块"，则登录后直接进管理后台。

### 品牌与英文 slogan

**不再使用「人话说八哥」这个别称**，界面上只保留英文 slogan + 中文软件全称（在关于页/页脚）。

主要候选（推荐第 1 个）：

| # | Slogan | 感觉 | 评价 |
|---|---|---|---|
| **1** | **Make errors make sense.** | 双关有力，和"看懂报错"完全对应 | ★推荐，短、好记、有含义 |
| 2 | Errors, in plain English. | 直白、功能性强 | 稳妥备选 |
| 3 | Understand every error. | 简单清楚 | 略平 |
| 4 | From error to understanding. | 有过程感 | 偏长 |
| 5 | Don't panic. Understand. | 情绪价值强 | 适合做副标题 |

**推荐组合**

```
品牌区主文案：Make errors make sense.
副标题：      Plain-English explanations for the vibe-coding era.
页脚全称：    代码异常智能解释系统软件 V1.0（Code Error Explainer）
```
